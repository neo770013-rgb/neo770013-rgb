# 请求关联与链路

本页提供“请求关联与链路”的工程设计与验证检查表，供接入或维护相关模块时逐项审阅。

## 设计约束

跨模块排障需要稳定关联标识，不能只依赖时间邻近。

## 落地检查

### 1. 明确输入与边界

在入口生成或校验关联标识。

### 2. 处理正常路径

向队列、日志和外部调用上下文传播。

### 3. 补齐确认与反馈

将业务意图标识与技术请求标识分开保存。

## 典型失效模式

一个业务操作可能包含多个重试请求。

## 验证场景

跟踪一次含重试的操作，检查可区分各次尝试。

## 审阅问题

用户提供的标识是否经过长度与字符校验？

## 评审记录

评审时记录适用模块、样本来源、验证结果及未解决项；尚未运行验证时标记为“待验证”，避免把设计建议当作已完成能力。
